# Standalone Windows Setup Design

## Контекст

Windows-приложение должно запускаться как один exe и работать с общей Supabase-базой без обязательного файла `.env` рядом с программой. При первом запуске пользователь должен ввести настройки подключения в локальном веб-окне, после чего приложение сохраняет их в профиле Windows и использует при следующих запусках.

## Решение

Добавляется слой runtime-конфигурации:

- portable override: `.env` рядом с exe или рабочей папкой имеет приоритет;
- постоянная настройка: `%APPDATA%\purchase-forecast-service\.env`;
- если настройки Supabase отсутствуют, открывается страница `/setup`;
- страница `/setup` сохраняет `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, bucket и опциональные `APP_USERNAME` / `APP_PASSWORD`;
- после сохранения сервер пересоздает объект хранилища отчетов, чтобы дальнейшие загрузки и расчеты шли через Supabase.

## Ограничения

- Секретный ключ не выводится обратно в HTML, логи или тестовые сообщения.
- Все пользовательские тексты нового экрана на русском языке.
- Существующий Docker/local режим продолжает работать через обычные переменные окружения.
- Реальные секреты остаются только в локальных `.env` файлах.

## Проверка

- Unit-тесты для приоритета загрузки `.env`.
- Unit-тесты для сохранения AppData-конфигурации.
- Unit-тесты для setup-страницы и валидации обязательных полей.
- Полный `python -m unittest`.
- Сборка `scripts/build_windows.ps1`.
