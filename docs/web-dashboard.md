# Веб-панель

## Назначение

Веб-панель - локальное окно в браузере для проверки заказов кулинарии. Она показывает ближайшие заказы, бюджет по категориям, логику прогноза и список данных, которые нужно прислать для точного расчета.

## Запуск

```powershell
docker compose up --build
```

Открыть:

```text
http://localhost:8000
```

API:

```text
http://localhost:8000/api/dashboard
```

## Текущие данные

Первый экран сервиса читает реальные локальные выгрузки:

- `data/local/culinary_sales_june_july.xlsx`
- `data/local/culinary_waste_june_july.xlsx`
- `data/local/Хранение и сроки годности, реализации.xlsx`

Если файл продаж не найден, сервис показывает демонстрационный блок из файла:

- `data/examples/purchase_items.json`

В демо-набор входят обед с курицей, салат Цезарь, ролл с курицей, суп дня и паста с курицей.

## Рабочий экран заказа

Основной маршрут `/` предназначен для ежедневной работы закупщика. На нем остаются только ближайшее окно заказа, итоговый объем, разбивка по дням, актуальная погода, предупреждения и компактная таблица позиций. Нажатие «Подробнее» открывает боковую панель со сроком хранения, прошлым сопоставимым периодом, списаниями, погодным коэффициентом и обоснованием решения.

Следующие окна показаны компактными карточками. Полная ретроспектива, погодная аналитика, роли меню и расширенные таблицы вынесены на `/analytics`; загрузка и архив файлов находятся на `/reports`; текущая конфигурация — на `/settings`.

Верхний блок показывает:

- общий объем заказа на 2 дня;
- сколько позиций собрано из целевых 34;
- недобор до цели;
- количество резервных позиций с высоким риском списаний;
- объем по категориям.

Также веб-панель показывает:

- будущие заказы по датам в схеме `Пн+Вт`, `Ср+Чт`, `Пт+Сб+Вс`;
- погодную сводку для каждого будущего окна заказа;
- правило окна заказа: для `Пт+Сб+Вс` сервис держит объем ближе к 2 дням и делает упор на позиции со сроком 3 дня;
- ретроспективу прошлой недели по тем же окнам `2/2/3`;
- сравнение фактических продаж с модельным объемом по прошлым окнам.
- сравнение продаж июня, июля и доступного августа по температуре и погодным условиям.

Позиции разделены на вкладки:

- `Постоянно` - стабильная база, которую стоит держать почти всегда.
- `Ротация` - сменные позиции небольшими партиями.
- `Резерв` - позиции, которые используются только если не хватает безопасных замен.
- `Исключить` - кандидаты на редкий заказ или временное исключение.

В таблицах колонка `Риск` раскрывает причину уровня риска: частоту попадания в списания, средний спрос и число дней с продажами. Колонка `Решение` показывает рекомендуемое действие и короткое основание: класс спроса, стабильность и срок годности.

В будущих заказах колонки `Продажи прошлого окна` и `Списания прошлого окна` показывают не весь период анализа, а ближайший предыдущий сопоставимый интервал. Например, для заказа `Ср+Чт` показываются продажи и списания прошлого `Ср+Чт`, а для `Пт+Сб+Вс` - прошлого окна `Пт+Сб+Вс`.

Для риска списаний используется гибрид:

- весь период анализа - базовый фон риска по SKU и отбор меню;
- прошлое сопоставимое окно - свежий сигнал для текущего заказа.

## Следующее обогащение

Нужно прислать:

- список позиций кулинарии;
- заказы или продажи за последние периоды;
- остатки перед заказом;
- списания;
- кратность заказа или производственной партии;
- пометки по дням: погода, акции, выходные, локальные события.
