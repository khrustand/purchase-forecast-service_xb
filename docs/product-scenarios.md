# Сценарии продукта

## Контекст

Сервис сейчас проектируется для заказов кулинарии. Кофе, молоко, упаковка и прочие расходники не входят в текущий фокус. Выпечка будет следующим этапом после того, как логика кулинарии станет понятной.

## Основные сценарии

1. Заказ на 2 дня: пользователь открывает панель и видит, сколько заказать обедов, салатов, роллов, супов и горячих блюд.
2. Разбор прошлых периодов: сервис принимает продажи, заказы и списания за прошлые периоды и считает средний спрос.
3. Контроль остатков: сервис вычитает текущий остаток из рекомендуемого заказа.
4. Риск нехватки: если остаток низкий или спрос вырос, позиция получает ручную проверку.
5. Риск списаний: если скоропортящейся позиции осталось больше прогноза, сервис предупреждает о возможном избытке.
6. Подготовка к выпечке: после стабилизации кулинарии добавляется отдельный расчет отпека.

## MVP

- Демо-позиции кулинарии в `data/examples/purchase_items.json`.
- Календарь заказов на 14 дней с шагом 2 дня.
- Доменная модель рекомендаций по прошлым периодам в `src/domain/culinary.py`.
- Веб-панель в Docker на `http://localhost:8000`.
- Список данных, которые нужно прислать для точного расчета.

## Первые интерфейсы

- Панель заказов: сумма, цикл заказа, ближайшие позиции.
- Логика прогноза: какие шаги применяет сервис.
- Данные для расчета: что нужно прислать следующим сообщением.
- Риски: нехватка, списания, нет истории продаж.
