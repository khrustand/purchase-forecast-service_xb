# AGENTS.md

## Назначение

Этот файл содержит локальные правила конкретного проекта. Общие правила starter kit подключаются из `.codex/starter/AGENTS.md`.

## Приоритет правил

1. Прямые инструкции пользователя в текущей задаче.
2. Локальные правила этого файла.
3. Текущий контекст, решения и ограничения из `.codex/project/project-context.md`.
4. Проектная документация: `README.md` и файлы из `docs/`.
5. Общие правила из `.codex/starter/AGENTS.md`.
6. Документация и prompts из `.codex/starter/`.

Если правила конфликтуют, сначала уточнить конфликт и не перезаписывать пользовательские изменения.

## Общие правила starter kit

Перед работой прочитать:

- `.codex/starter/AGENTS.md`
- `.codex/project/project-context.md`

Если эти локальные файлы отсутствуют после клонирования, использовать
`docs/developer-handoff.md`. Полный локальный контекст доступен в отдельном
приватном снимке данных; он не публикуется в Git.

Для ролевых задач использовать prompts из:

- `.codex/starter/prompts/`

## Локальные правила проекта

Заполнить эти разделы при bootstrap проекта и поддерживать их вместе с кодом.

### Стек проекта

- Frontend: HTML/CSS/JavaScript, шаблоны в Python HTTP-сервере.
- Backend / CLI: Python >=3.11, стандартная библиотека, без внешних зависимостей.
- Mobile: Android, Kotlin, Jetpack Compose, JDK 17, SDK 35.
- Database: локальные JSON/CSV/XLSX либо Supabase Postgres и Storage.
- Infrastructure: локальный Python, Docker Compose, Render; Windows exe через PyInstaller.

### Команды запуска, тестирования и сборки

- `.\.venv\Scripts\python.exe -m scripts.run_local` - запустить веб-панель с `.env`.
- `.\.venv\Scripts\python.exe -m unittest` - запустить тесты.
- `docker compose up --build` - собрать и запустить контейнер.
- `powershell -ExecutionPolicy Bypass -File scripts\build_windows.ps1 -InstallPyInstaller` - собрать Windows exe (нужен доступный скрипту системный Python).

### Архитектурные ограничения

- Держать доменную логику в `src/domain/` независимой от infrastructure adapters.
- Entry points, routing и dependency wiring размещать в `src/app/`.
- Работу с базами данных, внешними API, очередями, файловой системой и провайдерами держать в `src/infrastructure/`.
- Общие утилиты, типы и константы размещать в `src/shared/`.
- Новые директории добавлять только при понятной зоне ответственности и обновлять `docs/project-structure.md`.

### Данные и секреты

- Не хранить реальные секреты, токены, production-данные, приватные дампы и реальные пользовательские выгрузки в репозитории.
- Реальные значения переменных хранить только локально в `.env` или secret manager.
- В репозиторий добавлять только `.env.example`, `env.template` или документированные имена переменных.
- Локальные данные хранить вне репозитория или в явно игнорируемых директориях.

### Зоны, которые нельзя менять без согласования

- `.codex/starter/` - общие правила starter kit.
- Публичные API, CLI-команды, схемы данных и миграции, если изменение ломает текущие сценарии.
- Реальные данные пользователя, локальные выгрузки и содержимое `.env`.
- Сгенерированные отчеты или артефакты, если пользователь просит сохранить результаты предыдущих запусков.

## Контекст проекта

Текущий контекст, решения и следующие задачи хранить в:

```text
.codex/project/project-context.md
```

Обновлять этот файл после важных решений, milestones и крупных изменений.

## Язык вывода

- Все пользовательские сообщения, интерфейсы, отчеты, подсказки, ошибки и документация должны выводиться на русском языке.
- Технические идентификаторы, имена файлов, ключи JSON/API, команды и код остаются на английском, если это нужно для совместимости инструментов.
